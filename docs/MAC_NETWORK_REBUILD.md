# Mac 网络重建

入口为 **工具 → Mac 网络重建**。对象是整台 Mac 的系统网络服务，不限于当前代理或 Wi-Fi；预检按当前网络位置枚举服务，识别 Wi-Fi、以太网与 USB／雷雳以太网等 `en*` 接口。网桥、VPN 和其他特殊虚拟服务列为手动事项，不猜测其归属。

## 固定保留

- Wi-Fi 已保存网络、密码和自动加入偏好。不执行忽略网络、清除首选网络、修改无线网络列表或钥匙串操作，不读取或导出密码。
- 代理订阅、节点、Claude 桌面／CLI 登录资料、账号存档、检查设置、个人文件。
- 已停用的网络服务仍保持停用；第 3 层保留原网络位置用于回退。

不涉及企业描述文件、证书清理、驱动卸载、系统防火墙关闭、抹机或系统配置目录批量删除。

## 三个层级

| 层级 | 自动操作 | 手动事项与影响 |
|---|---|---|
| 1 · 全机连接刷新 | 刷新系统 DNS 缓存，按原配置依次重新连接已启用的物理网络服务 | 短暂断网；不修改地址方式、DNS、代理等持久参数。必要时在系统 TCP/IP 设置中手动续租 DHCP |
| 2 · 全机参数复位 | 清除已识别服务的手动 DNS、搜索域与代理绕过列表；关闭 HTTP、HTTPS、SOCKS、PAC 与自动代理发现；刷新并重新连接 | 手动退出会写回配置的代理／VPN 软件；保留服务结构、地址方式与启停状态。关闭代理不等于删除代理服务器字段或钥匙串中的认证信息 |
| 3 · 全机服务重建 | 创建新的空白网络位置，按原有接口顺序重建已识别物理服务；IPv4 使用 DHCP，IPv6 自动配置，保留停用状态；刷新 DNS，由系统建立新位置的动态路由 | 原网络位置保留，不自动删除。手动地址被改为 DHCP，需先确认网络支持自动获取。特殊虚拟服务不复制，须在所属软件中恢复；必要时重启 |

“全机”指枚举并处理当前网络位置内的全部已识别服务，包括停用的服务；不只处理当前默认出口。旧网络位置不再参与新位置的配置，但仍保留供回退。验证联网正常后，用户可在系统设置中手动删除不再需要的旧位置。

第 3 层没有强行清空整张内核路由表、删除所有 `utun` 或重启系统网络守护进程。由第三方软件创建的隧道和网桥需通过所属软件释放；原软件仍运行时，系统设置也可能被重新写入。

## 执行与恢复

1. **预检只读**：读取本地系统工具，不联网、不请求管理员、不初始化账号目录、不写日志或状态文件。显示自动处理清单、手动事项、保留项与阻塞原因。IP、DNS 地址、PAC URL 与 Wi-Fi 名称列表仅在内存中用于比对，不进入输出。
2. **核对并确认**：选择层级会使旧清单失效。执行必须带该层级与当前配置匹配的预检令牌；界面另需勾选影响确认并确认执行。
3. **执行前复核**：Claude 桌面、CLI 与本工具打开的隔离浏览器必须已退出；第 2、3 层还要求已识别的代理程序退出、系统 VPN 断开。管理员授权后再次核对网络配置和进程状态，变化时在修改前停止。
4. **系统授权**：一次授权内仅运行固定绝对路径的 Apple 系统程序。脚本通过 stdin 传递，不将用户可写脚本注册为 root 守护，不改变现有保镖与 root 权限边界。
5. **失败恢复**：连接刷新失败时尝试恢复刚被停用的服务。第 3 层中途失败时尝试切回旧位置并清理本次创建的新位置；失败不等于完全回滚，结果会保留待验收状态。
6. **重建后锁定**：状态记录保存到 `~/.claude-switcher/network-rebuild-pending.json`，权限 600；内容仅含层级、令牌、阶段和位置名称，不含网络凭据。关闭窗口或重启切换器不解除锁定，桌面切换、CLI 启动与隔离浏览器均被阻止。已有保镖不会被停止。
7. **恢复保护**：先连接网络、重新启用代理和 TUN，并恢复现有安全设置。第 3 层的系统默认 IPv6 与 Claude 保护要求是两个阶段；保护未恢复前不能启动 Claude。
8. **显式验收**：点击“检查保护环境”，核心完整安全检查通过后才删除待验收标记，再刷新 14 项界面状态。跳过项仍表示未验证，不会改成绿色通过。

执行期间不设置自动终止的超时，不允许从界面退出正在执行的操作。跨进程用户锁与 root 运行锁阻止重叠执行，并复用桌面／CLI／隔离浏览器的启动互斥，防止已开始的启动操作跨过重建检查窗口。异常中断后保留恢复记录，不自动重跑破坏性步骤或升级层级。如果 root 运行锁因系统异常残留，请重启 Mac 后恢复、验收。

第 3 层切换成功后，验收前可点击“切回旧位置”。它只切回原网络位置，不恢复第 1、2 层已经原位修改的参数，也不会跳过保护检查。若新位置已被用户手动切换，自动回退拒绝继续，改由系统网络位置界面处理。

## CLI

```bash
# 只读预检。LEVEL 为 1、2 或 3。
claude-switch.sh network-rebuild preview LEVEL

# 真正修改系统，要求先核对对应预检清单。
# TOKEN 是上一步 JSON 返回的 token；不应复用另一层级或过期配置的令牌。
claude-switch.sh network-rebuild apply LEVEL TOKEN

# 读取恢复状态，不联网。
claude-switch.sh network-rebuild state

# 第 3 层在验收前切回原网络位置；会请求系统授权。
claude-switch.sh network-rebuild rollback

# 恢复代理后执行完整检查，通过才解除启动锁定。
claude-switch.sh network-rebuild validate
```

所有命令都不自动删除订阅或账号数据，也不调用普通 `fix` 顺带修改时区、地区、语言和守护配置。网络重建操作不写客户端日志，诊断包不包含预检内容、位置恢复记录或网络配置。

## 验证记录与边界

- 后端测试提取核心内嵌模块并注入假系统。生成的管理员脚本也在隔离目录运行，但所有网络命令、进程查询和 root 锁路径已替换为假的实现；替换不完整时测试在执行前失败。
- 覆盖多接口、停用服务、特殊虚拟服务、静态地址提示、预检只读与脱敏、过期令牌、进程竞态、授权取消、部分失败、回退、锁定跨重启、符号链接拒绝、命令注入以及 Wi-Fi 列表复核。
- SwiftUI 模型与离屏渲染使用假核心，覆盖各层预览、确认、取消、恢复状态和启动阻断。
- **未在维护者本机执行重建或部署。** 系统授权实际交互、真实网络服务重建、各 macOS 版本上的 Wi-Fi 连接信息完整保留、真实 VPN 恢复和断网后的联网验收，仍需另行授权并在专门测试机验证。隔离测试通过不代表这些真机场景已经验收。

参考：[Apple 网络位置](https://support.apple.com/zh-cn/105129)、[Apple TCP/IP 设置](https://support.apple.com/zh-cn/guide/mac-help/mh14129/mac)。
