# TAG 本机适配与上游同步

这个分支从作者的 `main` 开始，保留 Git 历史，并把 TAG 适配作为独立修改维护。当前基线是上游 `cb6a72b255fde20f44d5157d5d6538c759458ae5`。上游源码及许可证归原作者；本分支不是官方发行版。

## 适配范围

- 核心脚本识别 TAG 的指定内核可执行文件，支持 `tag` 客户端模式；仓库保留上游默认值，安装器按实际客户端与出口写入配置。
- 保镖模板支持同一 TAG 身份判定；安装器可识别运行中的 TAG，也可手动选择 TAG。安装器和保镖模板仅做了隔离测试，未部署到系统。
- 新版桌面界面源码支持在客户端列表中显示 TAG，并说明检查更新与直接安装的区别；尚未重新打包或安装界面。
- 为防原版更新抹掉适配，`update` 和 `update --auto` 拒绝直接更新；更新入口在原版函数执行前拦截，保留其主体以便同步上游。`update-check` 检查经过校验的上游核心是否与适配基线一致。
- 原版界面和发行包不会因修改源码自动更新。旧版界面对 `skip` 和更新行为的提示也可能不同于本分支。

## 接收上游更新

1. 先检查本地改动是否已妥善提交，确认当前分支和运行中的安装状态。
2. 从 `upstream` 获取作者新提交，将 `upstream/main` 合并到适配分支；冲突逐项检查，不自动用任一侧覆盖另一侧。
3. 将 `TAG_UPSTREAM_CORE_SHA256` 更新为合并时上游原始 `core/claude-switch.sh` 的 SHA-256；这只用于识别上游核心变化，并不替代仓库工件校验。
4. 核对 TAG 进程身份、保镖、安装器、上游检查逻辑和更新保护；运行隔离测试，并重新生成 `SHA256SUMS`。有测试失败必须记录限制。
5. 合并到仓库不等于更新本机已安装版本。部署核心、App 或系统守护之前，分别确认版本、影响和当次授权。

当前这份仓库的修改可能尚未提交，也可能没有配置个人 GitHub 远程；以 `git status` 和 `git remote -v` 的实际输出为准。
